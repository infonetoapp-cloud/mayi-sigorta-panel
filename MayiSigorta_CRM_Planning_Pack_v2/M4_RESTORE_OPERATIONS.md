# M4 — D1 + R2 yerel/sentetik restore kanıtı

Nihai plan 14.1 ve Faz 4 kabul kapısı için offline recovery harness: `scripts/recovery/local-restore-proof.ts`. Uygulama import özelliği, Worker handler'ı veya production cutover değildir. `DOCUMENTS_ENABLED=false` korunur.

## İzolasyon ve yetki

`runLocalRestoreProof` hedef binding/path kabul etmez. Her denemede OS temporary dizininde yeni local D1, ayrı schema-reference D1 ve boş private local R2 namespace oluşturur. Wrangler yalnız `--local`, proxy yalnız `remoteBindings:false`, `envFiles:[]` kullanır. Normal application route/binding bağlanmaz; hedef DB/bucket çağırana verilmez. PASS dahil bütün hedefler harness-owned dispose/temporary-directory cleanup ile kaldırılır. Mevcut geliştirme DB'si, primary veya kaynak backup üzerinde mutasyon yetkisi yoktur.

Kaynak backup capability yalnız `get` içerir; normal CRM runtime `DocumentBackupAdapter.createAndVerify` sınırı değişmez. Backup delete/list/overwrite/admin yetkisi eklenmez. Negatif testlerde kendi sentetik fixture bucket'ını bozma/geri koyma hakkı test harness'ine aittir; ürün runtime yetkisi değildir.

Mevcut `DOCUMENT_RESTORE` job discriminator'ı korunur fakat bu offline tatbikat runtime Queue'ya enqueue edilmez. Felaket kurtarma hedefi ile aynı DB'ye bağlı normal Worker job'ı cutover otoritesi yapılamaz. İkinci Queue/lease/retry framework veya migration yoktur.

## Manifest sözleşmesi

Strict JSON `mayi-local-restore-v1`: app `0.1.0`, migration `0018`, canonical UTC creation timestamp, sentetik bookmark, orijinal native DB export SHA-256, expected object count, bütün tablo row count'ları, currency bazlı minor-unit toplamları ve `completion:COMPLETE`.

Her nesne agency/document/DocumentVersion/immutable backup-copy ID, exact generation, accepted `backup/UUID` key, SHA-256 ve uzunluğa bağlanır. Aynı key/copy/version-generation tekrarına veya çelişkisine izin verilmez. Accepted `documentBackupObjectKey` türetimi korunur. Server-owned canonical JSON serialization ve key-sorted nesne listesi manifest ID/hash üretir; JSON property sırası identity değiştirmez. Manifest/hash bir imza veya production provenance kanıtı değildir: production'da güvenilir manifest kaynağı ayrıca doğrulanmalıdır.

Nesne seti tüm kalıcı backup-copy evidence'ını, tarihsel kopyalar dahil, tam kapsar. Her AVAILABLE version için geçerli latest CLEAN/inspection ve tamamlanmış latest backup kanıtı gerekir. Non-AVAILABLE metadata kullanılabilir belgeye dönüştürülmez; karantinadan/primary'den fallback yapılmaz. DB-owned kopyayı listeden çıkarmak veya sahibi olmayan ek manifest entry koymak FAIL'dir.

## Test edilmiş doğrulama sırası

1. Strict/COMPLETE manifest, count/duplicate/key identity ve resource bounds; orijinal export byte hash.
2. Native local Wrangler D1 export'unun izole D1'e gerçek import'u. Fixture yazımları export öncesi durdurulur; tabloları farklı zamanlarda SELECT edip snapshot sayılmaz.
3. Local native dump tablo DDL/verisini iç içe çıkarır. FK açık D1 replay için in-memory SQLite yalnız SQL/value decoder olarak kullanılır: bütün tables/indexes, deferred-FK data, ardından historical triggers. Decoder ATTACH/DETACH/arbitrary SELECT/extension ve uygun olmayan PRAGMA'yı reddeder. Orijinal export hash'i dönüşümden önce doğrulanır. Native SQLite, gerçek local D1 restore kanıtının yerine geçmez.
4. `0000–0018` migration'larından temiz reference D1 oluşturulur; restored tables/indexes/triggers SQL fingerprint'leri birebir karşılaştırılır. CHECK ve unique constraints gerçek D1 import'unda uygulanır. D1 `integrity_check` PRAGMA'sını reddeder; decoder'ın integrity check'i ek kontroldür, D1 kontrolü diye sunulmaz. Gerçek restored D1 üzerinde `foreign_key_check` çalışır.
5. Bütün row count'ları; Customer/Policy/Renewal/Task bağları; initial/current history, allocation overflow/WON totals/cycles; audit actor bağları; job attempt/run/lease, scan/inspection/backup ve current-version ilişkileri doğrulanır. Non-null current pointer exact agency/document/AVAILABLE/latest version'a çözülmelidir; missing version INNER JOIN ile gözden kaçırılamaz. Run başlangıcı job creation'dan önce, bitişi başlangıçtan önce olamaz; scan zamanı run interval'i içinde ve CLEAN signature güncellemesinden sonra olmalıdır. Signature yaşı tarihsel scan anına göre en fazla 48 saattir; sealed eski snapshot'a bugüne göre freshness uygulanmaz. Meşru NULL pointer ve 30 gün geçmişe kaydırılmış tutarlı sentetik snapshot pozitif regresyonlarla korunur. Currency bazlı Policy, amendment, active allocation ve QuoteVersion toplamları Number yerine BigInt ile yeniden hesaplanır ve string minor-unit olarak manifestle karşılaştırılır.
6. Bütün Customer identity alanları önce all-null veya Customer türüne uyumlu eksiksiz zarf olarak doğrulanır; yalnız ciphertext non-null filtresiyle kısmi zarf atlanmaz. Mevcut zarf için exact `identity_key_version` recovery config gerekir. Accepted AES-GCM decoder ile her zarf çözülür; identity biçimi ve independent HMAC search hash doğrulanır. Kısmi zarf, eksik sürüm, yanlış AES veya HMAC key FAIL'dir. Meşru all-null optional identity anahtar gerektirmez. Test anahtarları yalnız sentetiktir; plaintext/key report'a yazılmaz.
7. Her exact kaynak backup nesnesi tam bounded body/EOF, uzunluk, immutable agency/version/generation metadata ve incremental SHA-256 ile okunur. Byte'lar yeni private namespace'e conditional-create edilir; restored nesne tekrar GET/full hash ile bağımsız doğrulanır. Fresh target inventory manifestle birebir eşleşir; surplus/ambiguous output FAIL'dir.
8. Güvenli report döner: manifest ID, app/schema, başlangıç/bitiş/süre, check flags, row count/para toplamları, object count/full checksum sonuçları ve final PASS/FAIL code. Customer metni, içerik, secret, key veya grant taşımaz. Exact manifest tekrarı timing dışında aynı evidence üretir; önceki PASS cache edilmez.

Ek tarihsel kontroller ödeme yöntemi/taksit semantiğini, LOST/VOIDED history kanıtlarını ve non-terminal history alanlarının boşluğunu kapsar; bugünkü katalog aktifliği şartı uygulanmaz. Her backup-copy için tam bir `document.backup.completed` SYSTEM audit gerekir: agency/version, job/run, correlation/idempotency, SUCCESS/BACKUP_VERIFIED ve strict job/run/attempt/generation/checksum metadata birebir eşleşir. Eksik veya çelişkili completion audit, nesne baytları doğru olsa bile FAIL'dir.

CompanyContact parent'ı COMPANY olmalıdır; CANCELLED/VOIDED veya arşivli kaynak poliçe açık renewal/takip taşıyamaz. Job completion creation'dan veya kendi run completion'larından önce olamaz; COMPLETED/DEAD/RETRY_WAIT için kendi exact son attempt'inin uygun terminal run kanıtı gerekir. `0018` erken DEAD backup/permanent-error investigation-code istisnası korunur. CLEAN dahil bütün scan outcome/run status eşleşmeleri denetlenir. History yalnız son state kontrolü değildir: bütün timestamp'ler 24 karakter canonical UTC/milisaniye parse-round-trip doğrulamasından geçer; tek canonical NULL→CONTACT_PENDING SYSTEM/POLICY_EXPIRING başlangıcından bütün timestamp bucket'ları nedensel bir zincir oluşturmalı ve mevcut state'e varmalıdır. Aynı milisaniyede UUID sırasına güvenilmez; bounded Euler traversal tüm geçişleri tüketir. Terminal vertex kapanılan açık stage'i de taşır; USER/REOPEN veya USER/WON_CORRECTED olmadan ya da farklı stage'e reopen FAIL'dir. Hem pure causal-chain testleri hem gerçek restored D1 üzerinde ters ID/INSERT sıralı aynı-milisaniye pozitif regresyonu vardır.

WON bağlantısı tarihsel kazanımı saklar: sonuç poliçesinin daha sonra iptal/arşiv edilmesi kazanım history'sini ve tahsisini silmez, restore başarısını engellemez. Açık renewal allocation'ı hâlâ ACTIVE/arşivlenmemiş sonuç poliçesi ister; LOST/VOIDED için ACTIVE link reddedilir. Sonradan iptal edilmiş WON sonuç poliçesinde de tam tahsis, currency, FK, cycle ve history kontrolleri korunur. Gerçek restored D1 + backup-byte regresyonları iptal/arşiv pozitiflerini ve açık allocation/eksik WON tahsis negatiflerini kapsar.

SUPERSEDED tahsis kendi değişmez tarihsel currency'sini korur; artık aktif bağlantı taşımayan sonuç poliçesinin meşru currency düzeltmesi eski tahsisi yeniden yazmaz. Güncel Policy currency eşitliği yalnız ACTIVE bağlantılarda aranır; aktif tahsis uyuşmazlığı, güncellenmiş manifest para toplamlarıyla dahi FAIL olur. Gerçek restored D1 + backup-byte regresyonu tarihsel TRY tahsisi ve güncel EUR poliçesi için PASS'i, aktif TRY/EUR uyuşmazlığı için kapalı hatayı doğrular.

Supersession yalnız FK kontrolü değildir: `supersedes_link_id` aynı agency/renewal/new_policy üçlüsündeki SUPERSEDED önceki link'e çözülmelidir. Değişmez supersession graph'ında döngü olamaz; bütün ACTIVE ve SUPERSEDED satırlar denetlenir. Gerçek restored D1 + nesne proof testleri geçerli aynı-milisaniye zincirinin PASS olduğunu, ACTIVE önceki link/yanlış renewal/yanlış policy ve tarihsel döngünün DB_DOMAIN_FAILED verdiğini doğrular. Bu negatiflerin her biri ilk RED koşusunda gerçek byte recovery ile hatalı PASS üretmiş; migration yerine yalnız post-import kontrolleri eklenmiştir.

Her tarihsel backup-copy, kendi run/job completion'ından sonra oluşturulmalı; completion audit copy'den önce olamaz. Copy'nin run başlangıcında mevcut exact-version/checksum CLEAN/inspection kanıtı ve copy zamanı itibarıyla scan generation ilişkisi gerekir. AVAILABLE olmayan eski kopyalarda da bu önkoşul aranır; copy sonrasındaki meşru INFECTED rescan ve RETIRED snapshot pozitif testle korunur. Quote pointer agency/quote/version bağı, SENT/ACCEPTED event ve receipt kanıtı, version sırası, product/branch/insurer ve optional installment semantiği ayrıca doğrulanır. Quote/Version/event/interaction actor graph'ı ve interaction Customer/CompanyContact bağı denetlenir; bugünkü katalog veya contact aktifliği tarihsel kayda dayatılmaz.

Evidence üretmemiş QUEUED satırlar dahil bütün DOCUMENT_SCAN/DOCUMENT_BACKUP job'ları exact agency/version/checksum bağına çözülmelidir. Generation dizisi 1'den kesintisiz ilerlemeli, önceki generation QUEUED/RUNNING/RETRY_WAIT iken yenisi bulunmamalı; QUEUED job attempt sayısı sıfır kalmalıdır. Her iki job türünde doğru evidence-free baseline mevcut backup nesnesiyle birlikte restore edilir; yanlış checksum, generation boşluğu, aktif generation çakışması ve QUEUED attempt bozulması gerçek restored D1 üzerinde DB_DOMAIN_FAILED verir. Migration veya ürün job framework'ü değiştirilmez.

Terminal Renewal'ın `closed_at`, kapanış aktörü ve LOST/VOIDED alanları mevcut sonucu oluşturan son timestamp bucket'ındaki **son expanded causal vertex'e giren** kapanış kanıtıyla eşleşmelidir; aynı bucket'taki önceki farklı-stage kapanışı yerine kullanılamaz. Aynı endpoint'lere sahip paralel kapanışlar nedensel olarak yer değiştirebilir; eşleşen gerçek bir final-edge adayı aranır, UUID/INSERT sırası belirleyici yapılmaz. History timestamp'leri ayrıca canonical UTC olarak doğrulanır. Geçerli WON baseline korunur; bozuk/canonical fakat history'den farklı kapanış zamanı ve farklı aktör reddedilir. Açık job run yalnız RUNNING job'ın güncel attempt/lease'ine ait olabilir; sonraki attempt başlamadan önce bütün önceki run'lar terminal/tamamlanmış olmalıdır. Geçerli STALE→RUNNING retry baseline geçer; iki açık run veya kapanış/başlangıç aralıklarının çakışması DB_DOMAIN_FAILED verir. Bu kontroller gerçek D1 restore ve mevcut nesne byte proof'una ulaşan RED→GREEN regresyonlarla kalıcıdır.

RETRY_WAIT job'ında `attempt_count < max_attempts` zorunludur; tamamlanmış run varlığı tükenmiş retry bütçesini yeniden açmaz. Immutable DocumentVersion numaraları her agency/document için 1'den kesintisiz ilerlemelidir; tek 7 numaralı sürüm veya ara sürüm boşluğu eksik geçmiş olarak reddedilir. Geçerli retry ve 1 numaralı sürüm baseline'ları mevcut backup nesnesiyle PASS; tükenmiş retry ve 7'den başlayan geçmiş gerçek native D1 üzerinde DB_DOMAIN_FAILED verir.

Immutable çıktılar iki yönde doğrulanır: mevcut evidence/copy kendi version/checksum/job/run kimliğiyle tutarlı olmalı; her COMPLETED BACKUP kendi exact son run'ına bağlı backup-copy, STALE dışındaki her COMPLETED SCAN kendi exact son run'ına bağlı scan evidence taşımalıdır. Backup-copy şemasında generation kolonu yoktur; generation exact run→job bağı, manifest nesne kimliği ve completion audit metadata'sından doğrulanır. Eski generation çıktısı yeni tamamlanmış job'ın eksik çıktısı yerine geçmez. Geçerli RETIRED tarihsel baseline korunur; çıktısız yeni SCAN/BACKUP ve FK-geçerli yanlış output version/checksum kapalı hatayla reddedilir. Native D1 ve gerçek nesne baytlarıyla doğrulanan seçki ayrıca yanlış generation/audit kimliği, tekrarlı proof determinizmi ve güncel canonical identity revocation kapısını kapsar.

Sınırlar: export 8 MiB, manifest 64 KiB, toplam 10.000 satır, 100 backup nesnesi, nesne başına accepted 20 MiB, tatbikat deadline 120 saniye, local import subprocess 60 saniye. Küçük sentetik fixture; enterprise backup orchestration değildir.

## Publication kapısı ve başarısızlık

PASS yalnız `VERIFIED_SEALED` demektir. Publication her zaman `SEALED_EXTERNAL_CONTROL_PLANE_PENDING`: runtime DB/R2 switch, belge activation, historical user/membership activation veya download route yoktur. Current offboarding/permission değişiklikleri ile deletion tombstone'ları haricî güncel kaynaktan uygulanıp canonical AuthIdentity/User/AgencyMembership + merkezi authorization evaluator üzerinden doğrulanmadan ortam açılabilir sayılmaz.

Kalıcı test, eski snapshot ACTIVE identity içerirken güncel sentetik D1'de identity REVOKED olduğunda canonical resolver/evaluator'ın DENY verdiğini ve restore PASS'inin bu DENY'ı veya sealed durumunu değiştirmediğini kanıtlar. Yeni/ikinci authorization sistemi icat edilmez. Gerçek güncel control-plane reconciliation ve cutover dış kabul kapısı olarak bekler.

Her failure kapalı report üretir; ham SQL/adapter exception report'a kopyalanmaz. Kaynak DB/primary/backup değiştirilmez, hedef yayımlanmaz. Cleanup başarısızlığı PASS sayılmaz. Kurtarma yetkisiyle kabul edilmiş backup'ı silmek veya başarısız restore sonrası kaynakları düzeltmek bu harness'in işi değildir.

Kaynak stream cancellation best-effort başlatılır; `cancel()` Promise'inin tamamlanması timeout/error report'u veya hedef dispose/dizin temizliğini bekletemez. Gerçek restored D1 üzerinden kalıcı regresyonlar, EOF vermeyen ve cancellation'ı kontrollü olarak pending kalan stream için `RESTORE_TIMEOUT`, ayrıca yanlış agency metadata'sı için `OBJECT_IDENTITY_MISMATCH` döndüğünü; cancellation henüz tamamlanmadan yalnız bu tatbikatın hedeflerinin kaldırıldığını doğrular. Test teardown kendi cancellation kapısını serbest bırakır; eski/başka geçici dizinleri temizlemez.

Bunlar production altyapı ve gerçek sorumlu onayı gerektirir. WhatsApp ve M5 bu restore dilimine dahil değildir.
